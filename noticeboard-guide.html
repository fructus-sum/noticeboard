01

Overview

Noticeboard turns one or more Raspberry Pis into a managed digital display system. One Pi runs the server and admin panel. Any number of additional Pis (or browsers on a local network) can act as display screens — showing slideshows of images and videos that you control remotely from the admin panel.

How it works

The system has three parts that work together:

PartWhat it doesWho uses it
Server Runs on one Pi. Stores all content, manages slideshows, and serves both the admin panel and display pages. Always running in the background
Admin Panel A web page (at /admin) where you log in, create slideshows, upload images, and control what appears on screen. You — the administrator
Display A browser page (at /) that shows the active slideshow. Can run on the server Pi itself or on separate display Pis. The audience — no interaction needed

When you make a change in the admin panel, the display screens update automatically within seconds — no page refresh required.

Every image and video is shown whole, as large as fits the screen, in its own shape: never cut off and never stretched, whether the screen is landscape or portrait. Any space left around it (for example, at the sides of a portrait picture on a landscape screen) is filled with the background colour, black unless you choose another (see Branding).

ℹ
The display screen requires no interaction and is designed to run unattended for months. Once set up, the Pi running the display can be left alone indefinitely: it recovers from outages and crashes by itself (see Running unattended) and even installs new versions by itself (see Automatic updates). If anyone needs the noticeboard's address, the faint pin in the top-left corner of any screen shows the Noticeboard server's address (see On the screen).

Running unattended

Nobody needs to touch a display, and it doesn't need anyone to click on it or keep it in focus. It keeps the slideshow moving by itself, whatever happens:

When…The display…
A slide is due to changeMoves on at the right time: images after their duration, videos when they end. It checks every 2 seconds that nothing was missed, so a slide can never get stuck on screen.
A slide won't appear (a download that never finishes, a video that won't start)Skips it after 30 seconds and carries on with the next one.
A video stops playing part-waySkips it after 30 seconds without progress. A video the browser paused, for example while the screen was asleep, is started again.
The screen sleeps and wakes, or the browser hides or freezes the pageCatches up as soon as the page runs again.
The server restarts, loses power or drops off the networkKeeps what it has on screen, reconnects by itself, and carries on within seconds of the server coming back. While nothing can load, it tries again every 30 seconds.
A new version is installedReloads itself onto the new version as soon as the server answers again.
Every slide keeps failingReloads the page (at most once every 30 minutes).
It has been running for a dayReloads once between 2 and 5 am, to clear anything the browser has built up over a long run.
A slideshow is published, disabled, scheduled on or off, edited or reorderedLets the slide on screen finish its full time (a video plays to its end), then starts the new running order from its first slide. A slide is never cut short.
The browser closes or crashesThe Pi opens it again after a few seconds, once the server answers.

A display only ever reloads once it has checked that the server answers, so a screen is never left on a browser error page. The slide timing has been tested over a simulated 30 days of running, with outages, sleep and missed timers along the way.

On the screen: the pin, the exit button, the warning mark and the cursor

ℹ
The exit button needs the kiosk set up by a recent installer. On a Pi installed before the exit button existed, run the installer again once (it keeps your answers and your content) and reboot. On a browser the Noticeboard kiosk doesn't run, such as a laptop showing the slideshow in full screen, press F11 or Esc instead.
02

Installation

One installer sets up both kinds of Pi: when it starts, it asks what the Pi is for. It needs a Raspberry Pi running Raspberry Pi OS with the desktop: the current release (Trixie) or Bookworm.

Option A — Single Pi (server + display on the same Pi)

Use this if you have one Pi that will both run the server and show the display on its own screen.

Open a terminal on the Pi

Press Ctrl+Alt+T, or find Terminal in the application menu.

Download and run the installer

Copy and paste the command below, then press Enter. You may be asked for your password.

Answer the installer's questions

When asked what the Pi is for, type 1 (Server + display). Then answer the sudo question — see the note below.

Wait for completion

The installer first brings the Pi's software fully up to date, then downloads Node.js, clones the project, builds the web app, and sets up a background service and automatic updates. The install itself takes 3–8 minutes depending on your internet connection; the update can take much longer on a Pi that hasn't been updated for a while.

Reboot the Pi

When the installer finishes, it asks whether to reboot: press Enter. After restarting, Chromium will open automatically in fullscreen kiosk mode showing the display, as soon as the server is ready. If the browser is ever closed or crashes, it opens again by itself.

curl -fsSL https://raw.githubusercontent.com/fructus-sum/noticeboard/main/installers/install.sh | sudo bash
⚠
Change your password after first login. The default admin password is Admin@12345. Anyone on your local network can reach the admin panel, so changing this immediately is important. See Section 3.
🔒
The sudo question. Raspberry Pi OS lets you run sudo commands without a password, so anything that takes over the Pi's user account can take over the whole Pi. The installer offers to make sudo ask for your password — we recommend answering y. It backs up the setting first and asks you to type your password once to prove it works, so you can't lock yourself out. If you answer n, nothing changes, and you can run the installer again later to change your mind.

Option B — Separate display Pi (remote client)

Use this if you already have a server Pi running and want to add an additional Pi as a second (or third) display screen.

Find the server Pi's IP address

Tap the faint pin in the top-left corner of the server Pi's screen: it shows the IP address and port. Or, on the server Pi, open a terminal and run hostname -I and note the first address shown (e.g. 192.168.1.42).

Run the installer on the display Pi

On the new display Pi, open a terminal and run the command below. When asked what the Pi is for, type 2 (Remote display). After your answers, it brings the Pi's software fully up to date before installing, which can take a while.

Enter the server URL when prompted

You will be asked: "Noticeboard server URL" — enter it in the format http://192.168.1.42:3000 (use the IP from step 1). Then answer the sudo question (see the note above).

Approve the display in the admin panel

If MAC filtering is enabled on the server, the new display will show its MAC address on screen. You must add it to the approved list in Admin → Settings before it can show content. See Section 9.

Reboot the display Pi

When the installer finishes, it asks whether to reboot: press Enter. Chromium will open automatically and connect to the server. Until the server answers, or while it waits for approval, the screen shows a waiting page with this Pi's MAC address; the slideshow replaces it by itself as soon as the server lets the display in (it checks every 10 seconds).

curl -fsSL https://raw.githubusercontent.com/fructus-sum/noticeboard/main/installers/install.sh | sudo bash

Give the server Pi a fixed address

Remote display Pis find the server by its IP address, so that address must not change. Most home and office networks hand out addresses automatically and can give a device a different one after a restart. If you use remote displays, fix the server Pi's address in one of two ways:

  • A reservation in your router (recommended): most routers can always give the same address to one device, often called a DHCP reservation or static lease. Your router's manual or its admin page explains how. You'll need the server Pi's MAC address, which the top of the admin panel's Slideshows page shows.
  • A static address on the Pi itself: set it in Raspberry Pi OS's network settings. The official Raspberry Pi documentation's networking pages explain how for your version of Raspberry Pi OS. Choose an address outside the range your router hands out.

If the server's address does change, run the installer again on each remote display Pi and give it the new address.

Running the installer again

You can run the installer again at any time — for example to point a display Pi at a different server, or to answer the sudo question differently. It offers your answers from last time, so pressing Enter keeps them. You never need to update the installer first: it always downloads and runs the newest version of itself from GitHub, from the branch the Pi follows (main unless you've switched), so what it sets up matches the version it installs. It never touches your slideshows, slides or settings.

On a server Pi that follows a branch other than main (see Switching branch), it also asks whether to keep that branch or go back to main. Enter keeps it. If you go back to main, it hands over to main's installer, which carries on with your answers.

Firewall (optional)

Just before it offers to reboot, the installer asks "Check this Pi's firewall?". Many Pis already have a firewall set up the way their owner wants, so it changes nothing unless you answer y.

You answer…What happens
nNothing is checked or changed. On a server Pi, the installer tells you the port to allow through your own firewall so other devices can reach the slideshow and admin panel: 3000, unless you've changed it. A remote display Pi needs no incoming port.
y, and a firewall is already onWith ufw or firewalld, the slideshow port is added and every existing rule is kept. Rules made some other way (your own nftables or iptables setup) are left exactly as they are, and the installer tells you which port to allow.
y, and there's no firewallIt offers to set up ufw, the firewall Raspberry Pi recommends. It asks "Set up a firewall now?" first.
⚠
Let the installer set up the firewall only on a dedicated slideshow Pi running Raspberry Pi OS. It blocks every incoming connection except the ones you choose, which could stop other things the Pi does. If this Pi does other jobs, answer n and set up its firewall yourself.

If you let it set up the firewall, it asks what must stay reachable before it blocks anything:

  • SSH (logging in from another computer): "Do you need SSH access to this Pi?" Its port is opened only if you say yes, even if SSH is installed, because an SSH port nobody uses is safer closed. It shows the port SSH is set to, usually 22; press Enter to use it, or type another. If you're connected over SSH at the time and say no, it warns you and asks you to confirm.
  • The slideshow port (server Pi): press Enter to keep 3000, or type another.
  • Remote desktop (VNC): asked only if VNC is running on the Pi.

It then allows those ports, plus 5353/udp so the Pi's .local name keeps working. Other incoming connections are blocked and outgoing ones allowed, and the firewall is turned on, starting with the Pi from then on. Any ufw rules you already had are kept.

🔓
You can't be locked out over SSH. If you run the installer over SSH and keep SSH, the installer turns the firewall on, then asks you to open a new SSH connection and answer y. If there's no yes within 3 minutes, or your connection drops, the firewall turns itself off again. Its rules are kept, so you can fix the port and turn it back on.
To…Run this on the Pi
See the firewall's rulessudo ufw status
Open another port later (e.g. 8080)sudo ufw allow 8080/tcp
Allow SSH latersudo ufw allow 22/tcp
Turn the firewall off / back onsudo ufw disable / sudo ufw enable

Accessing the admin panel after installation

Open any browser on your network and go to:

http://<your-pi-ip>:3000/admin
Replace <your-pi-ip> with the Pi's local IP address — e.g. http://192.168.1.42:3000/admin

On the Pi itself, you can always use http://localhost:3000/admin

Not sure of the Pi's IP address? Tap the faint pin in the top-left corner of any display screen — it shows the server's IP address and port. The pop-up closes with its ✕, or by itself after 90 seconds.

The admin panel is only ever at /admin, on the same port as the slideshow (3000). There's no separate admin port.

This guide is always at hand, and reading it doesn't need a login: the installer puts a Noticeboard Help shortcut on the Pi's desktop, and in the admin panel Help in the sidebar opens it in a new tab. From any device, it's at http://<server-ip>:3000/admin/help.

03

First Login

Logging in

Open the admin panel

Navigate to http://<pi-ip>:3000/admin in your browser.

Enter the default credentials

Password: Admin@12345 — this is the same for all fresh installations.

Change the password immediately

Go to Settings in the sidebar and set a strong password before doing anything else. Until you do, a red warning at the top of every admin page reminds you.

🔒
Security notice: The admin panel is accessible to any device on your local network. Always change the default password. The display page (/) does not require a password and is intentionally public on the local network so that any screen can show it.

Once you're logged in, the top of the Slideshows page shows this Pi's IP address and MAC address — handy if you need to reserve the Pi's address in your router or tell someone where to find it. It only appears after you log in.

The sidebar has, from the top: the logo (see Logo), Slideshows, Settings, Help ↗ (this guide) and Open viewer ↗, which opens the slideshow as the screens show it, in a new tab, while you stay logged in. At the bottom, Last updated shows when the noticeboard was last updated; it opens the project on GitHub.

The button at the top of the sidebar collapses it to a narrow column of icons, leaving more room for the page, and expands it again; hovering over an icon shows its name. On a phone the sidebar starts collapsed. Each browser remembers your choice. The admin panel works on phones: where a row doesn't fit across the screen, its buttons move onto a new line.

💡
A sample slideshow is ready to try. Every installation comes with a Sample slideshow, marked Sample in the list: five slides, four images that show for 3 seconds each and a short video that plays to the end. It isn't published, so the display won't show it until you click Publish. It shows off what the noticeboard can do, so software updates keep it current: when a new version comes with new or changed sample images, videos or settings, they're added to it. It can be hidden but not deleted. Put your own content in a slideshow of your own, since the sample's slides are replaced whenever its content changes.

Changing the admin password

Click "Settings" in the admin navigation bar
Scroll to the "Change Password" section

Enter your current password, then your new password twice. Click Save.

You will be logged out automatically

Log back in with your new password to confirm it worked.

Session behaviour

Admin sessions are stored as secure cookies and last until you log out or the session expires. You do not need to log in again after a browser refresh. If you get a "Session expired" message, simply log in again.

04

Creating Slideshows

A slideshow is a named collection of images and/or videos that plays on the display screen. You can have multiple slideshows and control which ones are active, when they appear, and in what order.

Creating your first slideshow

Go to Slideshows in the admin panel

Click "Slideshows" in the navigation bar at the top of the page.

Click "+ New slideshow"

A form will appear asking for a name.

Enter a descriptive name

Choose something meaningful like "Main Notices", "Weekly Menu", or "Events This Month". The name is only visible to you in the admin panel.

Click Create

The slideshow is created and appears in the list. It starts in Disabled status — it won't appear on the display until you publish it.

ℹ
New slideshows always start as Disabled. This lets you upload all your content and get everything set up before it appears on screen. When you're ready, click Publish. See Section 6.

Managing an existing slideshow

Click Manage next to any slideshow in the list to open its detail page. From here you can:

ActionHow
Rename the slideshowClick Edit in the Settings card, change the name, click Save
Change the scheduleClick Edit, change Schedule type, click Save
Change the priorityClick Edit, adjust the Priority number, click Save
Set how long its images showClick Edit, then under Image duration choose Use the default or Use its own and a number of seconds, click Save
Hide or unhide itClick Hide / Unhide in the Status field (only while it isn't published)
Publish or disableClick the Publish / Disable button in the Status field
Upload slidesClick + Upload in the Slides card
See a slide largerHover over its thumbnail, or click or tap it
Rename a slideClick the ✎ button next to the slide
Reorder slidesUse the ↑ ↓ arrow buttons next to each slide
Delete a slideClick the ✕ button next to the slide

Deleting a slideshow

From the slideshow list, click Delete next to the slideshow. You will be asked to confirm. Deletion is permanent — all uploaded media files for that slideshow will also be removed from the server. The sample slideshow is the one exception: it can't be deleted, but you can hide it.

Hiding a slideshow

To tidy away an old or seasonal slideshow without deleting it, click Hide next to it. Hiding only takes it out of the list: its slides, settings, schedule and everything else stay exactly as they are.

  • Only a slideshow that isn't published can be hidden. To hide a published one, click Disable first.
  • To see hidden slideshows, click Show hidden slideshows below the list. Click Unhide to bring one back; then you can publish it again.
  • The sample slideshow can be hidden and unhidden like any other.
05

Uploading Media

Each slideshow holds an ordered list of slides. A slide is either an image or a video clip. You upload them one at a time from the slideshow's detail page.

Supported file types

TypeAccepted formatsMax size
Images JPEG, PNG, GIF, WebP 500 MB per file
Videos MP4, MOV, AVI, WebM, MPEG 500 MB per file
ℹ
Images are automatically converted to PNG for consistent display. Videos are re-encoded to H.264 MP4 for reliable playback in Chromium. Images take a few seconds. Videos take longer: a large or long video can take several minutes on a Raspberry Pi. The slide shows processing meanwhile. You don't need to wait: carry on uploading, arranging and setting up your slideshows, and the video appears by itself once it's ready.

Uploading a slide

Open the slideshow's detail page

Click Manage next to the slideshow in the list.

Click "+ Upload" in the Slides section

A file picker will open. Select one image or video file.

Wait for the slide to process

You will see the slide appear in the list with a processing badge. This badge changes to ready when processing is complete. The page updates automatically — no need to refresh, and no need to wait: large videos can take a while, and you can carry on setting up meanwhile.

Repeat for additional slides

You can upload the next file immediately without waiting for the previous one to finish processing.

Slide status meanings

StatusMeaning
processingThe file has been received and is being converted. It will not appear on the display yet.
readyProcessing is complete. If the slideshow is published, this slide will appear on the display.
errorProcessing failed. The file may be corrupted or in an unsupported format. Delete it and try uploading again.

Previewing a slide

Each slide in the list has a thumbnail. To see one larger, hover over it, or click or tap it (on a touchscreen). Hovering shows the preview while the pointer stays on the thumbnail; clicking keeps it open until you close it with ✕, Esc or a click outside it, and lets you play a video. The preview is up to 500 × 500 pixels, keeps the slide's shape, and never enlarges a smaller slide. It opens over the page, so the ↑ ↓ buttons work as usual.

Naming a slide

Each slide in the list is shown by its name: at first, the name of the file you uploaded. To give it a clearer name, click the ✎ button next to it, type the new name and press Enter (or click elsewhere); Esc cancels. Clear the name and save to go back to the file's name. A name can be up to 200 characters. Renaming only changes what the admin panel shows: the file itself isn't changed, and nothing changes on the screens.

Slides uploaded before names existed show their type and when they were added (for example Image, added 12 Mar 2026, 14:02) until you rename them.

Video thumbnails

While a video is processed, the noticeboard also makes a thumbnail for it from a typical frame near the start. The video itself isn't changed. Videos uploaded before thumbnails existed have none; the slideshow's page then says so and offers Create thumbnails, which makes them the same way.

How long each slide displays

Images display for a fixed number of seconds. The default is 10 seconds, set in Settings → Display → Default image duration. A slideshow can use its own duration instead (click Edit on its page, then Image duration → Use its own); every slideshow without one uses the default. Changing the default never changes a slideshow that has its own.

Videos play from start to finish at their natural length before moving to the next slide.

When one slideshow follows another on screen, each slide keeps its own slideshow's duration. And when what's on air changes (a slideshow is published, disabled, scheduled on or off, edited or reordered), the slide on screen still gets its full time before the new running order starts.

A slide that can't be shown doesn't hold up the others. If a slide hasn't appeared after 30 seconds (a file that won't download, a video that won't start), the display skips it, and a video that stops playing for 30 seconds is skipped too. The slideshow keeps moving even while the screen is asleep or the page is hidden. See Running unattended.

Reordering slides

On the slideshow detail page, each slide has ↑ and ↓ buttons. Click these to move a slide up or down in the running order. The screens pick up the new order within seconds, once the slide they're showing has had its full time.

06

Publish & Disable

Every slideshow has a status — either Published or Disabled. Only published slideshows appear on the display. Disabled slideshows are completely hidden from viewers, regardless of any schedule settings, but you can still edit them freely in the admin panel.

Understanding the status buttons

http://192.168.1.42:3000/admin/slideshows
Slideshow list
Morning Announcements Published
4 slides · Priority 1 · Always active
Christmas Event Disabled
7 slides · Priority 2 · Always active
Lunch Menu Disabled
2 slides · Priority 3 · Scheduled (12:00–14:00)

The button shown tells you what will happen if you click it — and its colour clearly shows what action you're about to take:

ButtonCurrent statusWhat clicking does
Disabled Makes the slideshow live. It will appear on all displays immediately (subject to its schedule).
Published Removes the slideshow from all displays immediately. It can be re-published at any time.

Toggling from the detail view

You can also publish or disable a slideshow from inside its detail page. The status is shown in the Settings card alongside the same button. When a slideshow is disabled, a yellow warning banner is displayed at the top of the detail page as a reminder.

✓
Changes are instant. When you click Publish or Disable, all connected display screens update within 1–2 seconds via a live connection — no page refresh required on the display side.

Typical workflows

Setting up a new slideshow before going live: Create the slideshow (it starts disabled) → upload all your images → adjust the order and schedule → click Publish when ready.

Seasonal or event content: Upload your Christmas/event content weeks in advance. Leave it disabled. On the day, click Publish. After the event, click Disable. The content remains on the server ready for next year — just click Publish again.

Pulling content quickly: If you need to immediately remove something from display (e.g. outdated information), click Disable on the relevant slideshow. The change takes effect within seconds on all screens.

07

Scheduling

Each slideshow has a schedule that controls when it appears. This only applies to published slideshows — disabled slideshows never appear regardless of schedule.

Schedule types

TypeBehaviour
Always active The slideshow shows whenever it is published, 24 hours a day, 7 days a week. This is the default for new slideshows.
Timed The slideshow only shows during a specific time window (e.g. 09:00–17:00) on selected days of the week. Outside this window it is hidden even if published.

Setting a timed schedule

Open the slideshow detail page and click Edit
Change Schedule from "Always active" to "Timed"

Fields for Start time, End time, and Active days will appear.

Set your start and end times

These are in 24-hour format. For example, 09:00 to 17:00 means the slideshow appears from 9 AM until 5 PM.

Select which days it should run

Tick the days of the week. Leave all ticked for every day.

Click Save, then Publish if it isn't already
⚠
The schedule uses the server Pi's clock. Make sure the Pi's time and timezone are set correctly. Run sudo raspi-config and check Localisation Options → Timezone if you notice timing is off.

What happens when no slideshows are active

If no published slideshow matches the current schedule (or there are no published slideshows at all), the display shows the words No slideshow published on the background colour (black unless you choose another), with the logo above them (see Branding). This is not an error: publish a slideshow, or check its schedule, and the display switches to it within seconds. A black screen with only a faint pulsing dot means something else: the display can't reach the server.

08

Ordering & Priority

When more than one slideshow is published and scheduled at the same time, the system uses priority to decide which ones appear. Up to 5 slideshows can run simultaneously (their slides are merged into one continuous playlist in priority order).

Priority numbers

Lower numbers = higher priority. A slideshow with priority 1 appears before one with priority 2. When you create a slideshow, it gets the next available priority number automatically.

PriorityBehaviour
1Highest — slides from this slideshow appear first in the playlist.
2 – 4Slides are appended after higher-priority slideshows.
5+Included if up to the 5-slideshow limit hasn't been reached.
> 5 active at onceOnly the top 5 by priority number are shown. The rest are ignored until one of the top 5 becomes inactive.

Changing priority

Open the slideshow's detail page, click Edit in the Settings card, change the Priority number, and click Save.

Slide order within a slideshow

Inside a single slideshow, slides play in the order shown in the Slides card. Use the ↑ and ↓ buttons to reorder them. The playlist cycles continuously — after the last slide, it loops back to the first.

09

Remote Displays

Any device on the same network as the server can open the display page at http://<server-ip>:3000/ — including laptops, tablets, and additional Raspberry Pis. If you want to restrict which devices can see the display, use MAC filtering. Remote display Pis reach the server by its IP address, so give the server a fixed address (see Give the server Pi a fixed address).

MAC filtering

MAC filtering lets you create an approved list of devices. When enabled, only approved devices can access the display and admin panel. Unapproved devices see a "Not Found" error.

ℹ
MAC filtering is disabled by default. You only need to enable it if you want to restrict which screens can show your content — for example, in a public-facing installation.

Enabling MAC filtering and adding a device

Find the MAC address of the device you want to approve

If the device already tried to connect and was blocked, a remote-display Pi will show its own MAC address on screen. On other devices, check the network settings or run ip link show in a terminal.

Go to Admin → Settings → MAC Filtering
Add the MAC address to the approved list

Enter the MAC address (e.g. aa:bb:cc:dd:ee:ff) and a label so you remember which device it is.

Enable MAC filtering

Toggle "MAC filtering enabled" to on. The server Pi itself (localhost) is always approved automatically.

⚠
Add your own device to the approved list before enabling MAC filtering. If you enable it without adding the browser you're using, you will be locked out of the admin panel. If this happens, SSH into the Pi, edit /opt/noticeboard/data/config.json, and set "enabled": false in the macFiltering section, then restart the service.

When you tick Enable MAC filter, a pop-up reminds you of this before anything changes. If the noticeboard can tell the MAC address of the device you're using, the pop-up shows it with an Add it to the list button. How to find your MAC address opens simple steps for Windows, Mac and Linux; its OK takes you back. Cancel unticks the box, and Turn on MAC filtering keeps it ticked: filtering starts when you click Save. Addresses copied from Windows, with dashes, are fine.

Folding the cards away. Each card on the Settings page and on a slideshow's page can be folded away to its title: click the title (or its ▾) and click again to open it. Your browser remembers which cards you folded. A card that holds a warning, such as Change password while the default password is in use, or Software updates after an update went wrong, stays open until the warning is dealt with. The warnings at the top of the page are never folded away.

Branding

The Branding card in Settings sets the logo and the background colour of the screens.

The logo is shown above No slideshow published on every screen when nothing is on, and above the title in the admin sidebar.

  • Upload a logo… takes a PNG, JPEG, GIF or WebP image. If it's bigger than 500 × 500 pixels, it's scaled down, by its larger side, to fit. Its shape is kept, it's never stretched, and a smaller image is never enlarged.
  • Use the default logo goes back to the Noticeboard logo.
  • Show the logo turns it on or off, on the screens and in the sidebar together.

The background colour fills the screen around a slide that doesn't fill it, and behind the logo when nothing is published. Pick a colour, or type its code (# and six digits or letters a–f, for example #000000 for black or #ffffff for white), then Save. Every screen changes within a few seconds; the logo preview shows it on the chosen colour.

Deleting your content

The Delete content card at the bottom of the Settings page has Delete All…. It deletes every slideshow except the sample slideshow, with all their slides and files. The sample slideshow (and whether it's published or hidden), your settings, the logo and the background colour are kept: it isn't a factory reset.

Because it can't be undone, it asks three times, like switching branch: first it lists every slideshow it will delete and how many slides each has; then it asks for the admin password; then it gives you a last chance to back out. Cancelling at any step, or a wrong password, changes nothing. Screens stop showing the deleted slideshows straight away.

Restarting the server service

Some settings changes (e.g. port changes, or manual edits to config.json) require restarting the server. Run this command on the Pi via SSH or a terminal:

sudo systemctl restart noticeboard

Checking service logs

If something isn't working, the service logs are the best place to look for error messages:

sudo journalctl -u noticeboard -f

Press Ctrl+C to stop following the log.

Automatic updates

The server Pi keeps itself up to date with Noticeboard on GitHub, following one branch of it: main, the stable version, unless you choose another (see Switching branch). Every 15 minutes it checks for a new version; if there isn't one, nothing happens. If there is, it installs it, rebuilds the app and restarts the server. The screen goes dark for a few seconds, then every display — including remote display Pis — reloads itself and shows the new version. Nobody needs to touch the screens. Automatic updates cover the Noticeboard app itself; the way the Pi starts its display (the kiosk) is set up by the installer, so a change to that needs the installer run again.

ℹ
Updates are careful. An update waits while an upload is being processed. If a new version fails to install or doesn't start, the Pi puts the previous version back, keeps running it, and skips that version until a newer one is published. Updates never change or delete your slideshows, slides or settings. The updater runs as the Pi's normal user, so it never needs sudo.

Last updated, above Log out in the admin panel's sidebar, shows when the noticeboard was last updated: when it installed the version it runs, the same time as Last update in the Software updates card. It changes only when an update is installed, not every time you open the page. Hover over it to see the version and when that version was made (on a copy that hasn't been updated by the updater or the installer, it shows that date instead). Click it to open the project on GitHub.

The Software updates card at the bottom of the Settings page shows:

LineWhat it tells you
RunningThe branch and version (a short code such as 5b6d51f) the noticeboard is running now.
UpdatesHow often it checks, and when it last checked and what it found: up to date, waiting for an upload, GitHub unreachable, and so on.
Last updateThe result of the last update or branch switch: Done, Rolled back, Cancelled or Failed, with what happened in plain words.

When the installer needs running again

Updates change the Noticeboard app, but not what only the installer sets up on the Pi: the kiosk that shows the slideshow full screen, the system services, the desktop shortcuts and system packages. When a new version (or a branch you switch to) changes one of those, an amber box at the top of every admin page says Run the installer again on this Pi. It lists what running it brings and shows the command to run, with a Copy button. The command is for the branch the Pi follows. Until the installer has been run, every screen also shows a small red warning triangle in its bottom-right corner (see On the screen).

Run it in a terminal on the server Pi, or over SSH. It keeps your answers (press Enter), slideshows and settings, and offers to restart at the end. The box goes away once the installer has run; there's nothing to close. Until then the noticeboard works as before, just without what the box lists. If the box says so, run the installer on each remote display Pi too.

Before you switch branch, the check tells you if that branch will need the installer run again (see Switching branch).

Switching branch

Besides main, the project on GitHub can have other branches holding work in progress, such as a new feature being tried out. You can switch this noticeboard to one of them from the admin panel. Updates then come from that branch until you switch back. Nothing changes until you've checked the branch and confirmed twice.

Choose and check the branch

In Settings → Software updates, type the branch name or pick it from the list, then click Check branch. The noticeboard checks that the branch exists on GitHub and can be used, and shows the change: the branch and version running now → the new branch and its version, with its latest change. It also checks the software on this Pi against the list the branch keeps of what it needs (see below), and says if the branch will need the installer run again on this Pi after the switch (see When the installer needs running again). Nothing has changed yet.

Read the warning and enter the admin password

Click Switch to …. A warning explains that the branch is experimental, may not work with this setup, may be unstable, and may change how it stores your data. Enter the admin password and click Continue. A wrong password cancels the switch and changes nothing. After 5 wrong passwords, wait 15 minutes before trying again.

The final warning

"Last chance to avoid doing something stupid!" Your password has already been accepted; this is your last chance to back out. Cancel leaves everything exactly as it is. Confirm starts the switch straight away.

The switch runs by itself

The new branch is saved as the one updates come from, and the normal update process starts at once, from that branch. The card follows it: it installs and builds the new version while the noticeboard keeps running, then restarts it. The screens go dark for a few seconds and reload by themselves, and the admin page reloads onto the new version. Every later update comes from the new branch until you switch again.

⤴
When the branch is merged into main, the noticeboard goes back to main by itself. A branch is usually temporary: once its features are finished, they're merged into main. When all of the branch's work is part of main, the next update check (within 15 minutes) switches the noticeboard back to main, so it gets main's updates again. This happens whether the branch was merged, squashed or rebased, and also if it was deleted after being merged. A branch deleted without being merged is left alone, because its features aren't in main. When the noticeboard has gone back, a notice at the top of every admin page says so. It stays until someone closes it with ✕, which closes it on every page. If going back fails, it's undone like any other switch, and tried again once main has a new version.

Software a branch needs

Besides the parts it installs by itself, the noticeboard needs some programs on the Pi: Node.js, npm, Git, FFmpeg, curl and Chromium. A branch can need newer versions, or programs main doesn't, so every branch keeps a list of what it needs (system-requirements.json). When you check a branch, the Pi compares its own software with that list:

  • Everything's there: a green line lists the versions found.
  • Something is missing or too old: an amber box names each program, the version the branch needs, what this Pi has, what it's for, and how to install it. Install it yourself before switching: the switch doesn't install system software. If you switch anyway, an extra Missing software confirmation comes first, which you have to tick to continue, and the final warning reminds you what's missing.
  • The branch keeps no list (it's older than these checks): the card says it can't be checked.

Some branches can't be chosen, and the check says why: a branch that doesn't exist; one older than branch switching (the Pi couldn't be switched back from the admin panel afterwards); and one with files in the places the noticeboard keeps its content and settings (data/, tmp/, logs/ or .env).

↩
A switch that fails is undone by itself. If the branch can't be downloaded or turns out to be unusable, the switch is cancelled and nothing changes. If it fails to install, the previous branch and version are put back (the noticeboard kept running the old version the whole time). If it installs but doesn't start, the previous branch and version are put back and restarted. Either way, updates go back to following the previous branch, and the Software updates card says what happened.

Your data is kept. Switching never deletes anything. Slideshows, slides and media stay exactly where they are. Before each switch, the settings (config.json and each slideshow's slideshow.json) are copied to /opt/noticeboard/data/backups/, in a folder named after the time and the branch switched from, in case the new branch changes them. To go back to those settings, copy the files back and restart the service.

If a switch starts at the next check (within 15 minutes) rather than straight away, the Pi's installer ran before branch switching existed: run it once to make switches start at once.

⚠
If the Software updates card says putting the previous version back failed, the noticeboard is still running, but might not start after a restart. Run the installer on the server Pi: it installs the branch in the settings again, or offers to go back to main. Your content is untouched.

Troubleshooting

Display says "No slideshow published" or stays black

No slideshow published means the display is connected but has nothing to show. A black screen with only a faint pulsing dot means it can't reach the server. The usual causes:

CauseHow to checkFix
No slideshows are published Open the admin panel. Do any slideshows show Published? Click Publish on a slideshow
Published slideshow has no ready slides Open the slideshow. Are any slides showing ready? Upload images and wait for processing to complete
Schedule doesn't match current time Check the slideshow's schedule setting Change schedule to "Always active" or adjust the time window
Server not running Can you open the admin panel? Is the URL reachable? Run sudo systemctl restart noticeboard

Admin panel shows "Session expired" or logs me out

Simply log in again. Sessions expire after a period of inactivity. If you are repeatedly logged out very quickly, restart the server — the JWT secret is regenerated on a fresh install and that can occasionally cause stale session cookies.

sudo systemctl restart noticeboard

Uploaded image/video doesn't appear after processing

Large videos can take several minutes to process: while a slide shows processing, just wait, and it appears by itself. Once it's ready, check that the slideshow is published and that the schedule is currently active. If the slide shows error, delete it and try uploading again. For videos, check that ffmpeg is installed on the Pi:

ffmpeg -version

If it's not found, install it:

sudo apt-get install -y ffmpeg

Remote display Pi won't connect / shows MAC address screen

If the display Pi shows its MAC address and says it's waiting for MAC address approval, it can reach the server, but MAC filtering is blocking it. Add its MAC address to the approved list in Admin → Settings → MAC Filtering; the slideshow appears by itself within about 10 seconds. If it says it's waiting for the Noticeboard server, it can't reach the server at all: check the server Pi is on and running, and that the address on screen is right (to change it, run the installer on the display Pi again). A display Pi set up with an older installer may keep showing the MAC address screen after approval until it's rebooted; run the installer on it once to fix that.

Display is connected but slides seem slow to update after a change

The scheduler checks for schedule changes every 60 seconds. If you change a schedule setting, wait up to 1 minute for the display to update. Uploads, publishing, disabling, reordering and deleting slides take effect within seconds, but always after the slide on screen has had its full time: with 10-second images, allow up to 10 seconds more (a video plays to its end first). A video that's still processing appears by itself once it's ready.

Can't get out of full screen on a display

Move the mouse (or tap the screen, or press a key): the exit button appears in the top-right corner. Click it and confirm, and that screen's browser becomes a normal window (see On the screen). If no exit button appears, the Pi's kiosk was set up by an older installer: run the installer again on that Pi and reboot. Until then, from another computer you can log in to it over SSH and stop the kiosk with pkill -f kiosk; it comes back at the next reboot.

The admin panel is hard to use on the Pi itself

Leave full screen with the exit button first, then open the browser from the desktop and go to http://localhost:3000/admin. Since the kiosk runs in a browser profile of its own, that's an ordinary browser window. On a Pi set up by an older installer, a browser opened from the desktop could open inside the full-screen kiosk; run the installer again once to fix that.

The location pin shows an unexpected address

The pin always shows the Noticeboard server's address, even on a remote display or on a laptop, because that's the address other devices need. If the server has several network connections (e.g. wired and Wi-Fi), each is listed, the one this screen uses first. If the address keeps changing, give the server a fixed address (see Give the server Pi a fixed address).

A video has no thumbnail

Videos uploaded before thumbnails existed have none. Open the slideshow in the admin panel and click Create thumbnails. If it says the last try failed, check that ffmpeg is installed (see below).

The Pi display is blank or black on boot (kiosk doesn't start)

The kiosk waits for the server to be ready before launching Chromium, and opens Chromium again if it ever closes or crashes. If the server takes longer than usual to start (e.g. after a system update), the kiosk still launches — just more slowly. Check the server is running:

sudo systemctl status noticeboard

If the service is failed, check the logs for why:

sudo journalctl -u noticeboard --no-pager -n 50

If the Pi reaches the desktop but the browser never opens, the kiosk's own log says what it did during this boot:

journalctl -t noticeboard-kiosk -b

Waiting for the server with nothing after it means the server isn't answering (check it as above). Browser exited … starting it again means the browser closed and the kiosk reopened it, as it should. Chromium isn't installed, or an empty log, means the kiosk setup is from an older installer: run the installer again and reboot. Older installers didn't know that newer Raspberry Pi OS calls the browser chromium instead of chromium-browser.

The slideshow seems stuck, or the screen goes dark

The display moves on by itself from any slide that won't load or play (after 30 seconds at most), catches up after the screen sleeps, and reconnects after an outage (see Running unattended). If a screen still looks stuck:

  • The same slide for a long time: it may be a long video. Videos play to the end.
  • The screen goes black after a while: that's Raspberry Pi OS blanking the screen, not the noticeboard. Turn it off with sudo raspi-config → Display Options → Screen Blanking → No, then reboot.
  • A faint pulsing dot on black: the display can't reach the server. It reconnects by itself once the server is back; check the server as described above.
  • Only some slides show: the others may not have finished processing, or failed to. Check them in the admin panel.

An update hasn't appeared on the screen

The server Pi checks for updates every 15 minutes and waits while an upload is being processed, so allow about 20 minutes. Settings → Software updates in the admin panel shows the branch and version running, the last check and the last update. Updates only come from the branch shown there, so a change on another branch won't appear. For more detail, see what the updater did:

sudo journalctl -u noticeboard-update --no-pager -n 30

If it says it is skipping a version, that version failed to install or start, so the Pi went back to the previous one. It installs the next version automatically once one is published; to retry the skipped one anyway, run bash /opt/noticeboard/installers/update.sh --force. If the log is empty, the Pi was probably installed before automatic updates existed — see Automatic updates.

A branch switch didn't happen, or was undone

The Last update line of Settings → Software updates says what happened:

It saysWhat it means
CancelledThe switch never started, so nothing changed: the branch couldn't be downloaded (is the Pi online?), was unusable, or its latest version had already failed once. Try again later, or choose another branch.
Rolled backThe new branch failed to install (it didn't build, or its downloads failed) or didn't start, so the previous branch and version were put back. Nothing else changed. Try again later, or choose another branch.
FailedPutting the previous version back failed too. Run the installer on the server Pi, as the message says (see Switching branch).
Waiting to start for a whileAnother update, an upload or the installer is running. The switch starts at the next check, within 15 minutes.

Other devices can't reach the slideshow or admin panel

If it works on the server Pi itself (http://localhost:3000/) but not from other devices, a firewall is probably blocking the port. On the server Pi, check with sudo ufw status. If ufw is on and port 3000 isn't listed, allow it with sudo ufw allow 3000/tcp, or run the installer again and let the firewall step do it (see Firewall). If you use a different firewall, allow TCP port 3000 in it. Also check that both devices are on the same network.

sudo now asks for a password

That's expected if you answered y to the installer's sudo question: commands that start with sudo now need your Pi user's password. To go back to no password, copy the saved setting back. The installer printed the exact command when it made the change; on most Pis it is:

sudo cp /root/noticeboard-sudoers-backup/010_pi-nopasswd /etc/sudoers.d/

How to check everything is working

From the Pi's terminal, this one-liner confirms the server is up and accepting connections:

curl -s -o /dev/null -w "HTTP %{http_code}\n" http://localhost:3000/
# Should print: HTTP 200
